--------------------------------------------------------------------------------
1. PROJECT OVERVIEW & PURPOSE
--------------------------------------------------------------------------------
- Application Name: Haedo Futsal App (haedo-futsal-app)
- Repository Name: WillyBit78/WebApp-HF
- Application Type: Progressive Web App (PWA) for Comprehensive Sports Club Management.
- Primary Objective: Manage club membership roster (Socios), monthly fee collection and payment verification via OCR transfer receipts or cash, institutional notices with web push notifications, match & event calendar, role-based user management (Admin, Adm.Club/Contador, Coach, Staff, Member/Socio), and official club store.

--------------------------------------------------------------------------------
2. CONNECTED PLATFORMS & INTEGRATION (.env LOCATION)
--------------------------------------------------------------------------------
The project is integrated with three core services:
1. GitHub: Core code repository (WillyBit78/WebApp-HF).
2. Supabase: Backend-as-a-Service (PostgreSQL Database, Auth, Storage for face photos and payment receipts).
3. Vercel: Continuous Deployment hosting linked to the GitHub repository for automatic builds on push.

CRITICAL: ALL CREDENTIALS, API KEYS, AND TOKENS ARE STORED IN THE ENVIRONMENT FILE .env LOCATED AT THE PROJECT ROOT (Z:\Willy\Proyectos\App Club\Nueva APP\.env).

Keys stored in .env include:
- Supabase URL & Public/Service Keys
- PostgreSQL Connection String / Supabase Pooler
- Mercado Pago Access Token
- VAPID Keys for Web Push Notifications
- Google Gemini API Key (for receipt OCR processing)

4. TECH STACK & ARCHITECTURE
--------------------------------------------------------------------------------
- Frontend Framework: React 18 + Vite + Tailwind CSS 3 + Lucide React + clsx + tailwind-merge.
- Backend & DB: Supabase (@supabase/supabase-js) + PostgreSQL (pg).
- PWA & Service Worker: Web Share Target (sw.js), Web Push Notifications (web-push), Web App Manifest.
- Payment Receipt OCR: @google/generative-ai (Gemini Flash 1.5/2.0) + pdfjs-dist (PDF to canvas rendering).
- Layout & Navigation: Responsive, role-based (App.jsx, desktop Sidebar.jsx, mobile BottomNav.jsx, top Navbar.jsx).

5. FEATURE BREAKDOWN & HISTORICAL CONFIGURATIONS
--------------------------------------------------------------------------------

A. ROLE-BASED NAVIGATION & PERMISSIONS
   - Socio (Member): Home/Dashboard, Calendar, Notices, Store.
   - Staff: Home/Dashboard, Calendar, Notices, Store, Member Roster (Gestión de Socios).
   - Coach: Home/Dashboard, Calendar, Notices, Store, Member Roster (Gestión de Socios), Cash Fee Collection.
   - Adm.Club / Contador (Accountant): Home/Dashboard, Member Roster, Financial Control (Income/Expenses/Audit), Calendar, Notices, Store.
   - Admin: Full system access (Socios, Calendar, Notices, Store, Financials, System/Staff Config).

B. PANEL PRINCIPAL (MAIN DASHBOARD SUMMARY - MainDashboardSummary.jsx, App.jsx)
   - Initial View: All staff roles (admin, contador, coach, staff) land on Panel Principal (currentTab = 'dashboard') upon login.
   - Structured Card Order:
     1° ESTADO DE CUOTAS MENSUAL: Large 3D Donut Chart, % AL DÍA centered badge, and fee breakdown (Al Día, En Revisión, Pendientes, Total Padrón). Direct navigation to Gestión de Socios (users).
     2° COMUNICADOS DEL CLUB: Summary of active notices, notice count, and latest official announcement title. Direct navigation to Comunicados (notices).
     3° SECTOR FINANZAS (Staff Admin/Contador): Net monthly balance, income vs expenses breakdown. Direct navigation to Finanzas (finance).
     4° AUDITORÍA DE PAGOS (Staff Admin/Contador): Pending receipt audit count. Direct navigation to Auditoría (finance with en_revision filter).
   - Clean Screen Navigation: MainDashboardSummary is excluded from DashboardContador.jsx so opening Finanzas or Auditoría displays the clean targeted module without top summary cards.
   - Removed: Socios Activos card was completely eliminated to prevent redundant data.

C. MEMBER ROSTER & STAFF MANAGEMENT (DashboardSocios.jsx, ModalAddUser.jsx, ModalFichaSocio.jsx)
   - Top Header Panel: Replaced top cards with 3D Donut Chart card (% AL DÍA centered) + padrón details breakdown. Removed redundant headers.
   - Toolbar: Search bar occupies full width; eliminated redundant filter buttons.
   - Compact Hierarchy Gauges: Mini circular Donut SVG gauges positioned strictly on the RIGHT side of card headers across all screen sizes (mobile & desktop) next to collapse arrows.
   - Coach Assignment Display: Discipline and Category headers display assigned Coach/DT badges (e.g. Coach: Juan Pérez).
   - Staff Registration & Editing:
     * Single "Nombre" field (Apellido removed). Entered name automatically populates Username (@nombre).
     * Role selection: Staff (no finance access), Coach (includes multi-select checkboxes for assigned sports categories from CLUB_CATEGORIES), Adm.Club (Contador permissions).
     * Fee section hidden for Staff. Save button reads "Guardar Staff" / "Guardar Cambios".
     * Staff Accordion positioned below all sports disciplines; header simplified to "Staff e Integrantes del Club".
     * ModalFichaSocio.jsx staff edit mode is identical to ModalAddUser.jsx, allowing admins to reassign categories or roles at any time.

D. PERSISTENT NOTIFICATION BADGES (Navbar.jsx, AppContext.jsx)
   - Strict string ID normalization (String(id)) stored in localStorage (haedo_read_notice_ids and haedo_viewed_payment_ids).
   - Clicking notice or payment notification badges in Navbar permanently clears unread counters so badges never reappear on reload for those items.

E. INSTITUTIONAL NOTICES MODULE (NoticeBoard.jsx, AppContext.jsx)
   - Direct Supabase persistence (notices table) with explicit exception handling.
   - Automated Web Push Notifications broadcast to all subscribed devices upon publication.
   - Sender name formatted as clean name without role brackets.

F. OCR RECEIPT READER, WEB SHARE TARGET & PAYMENTS (PaymentUploader.jsx, sw.js)
   - Android PWA Web Share Target (sw.js): Intercepts native POST requests to /share-receipt when sharing PDF/Image bank receipts directly from banking apps.
   - Hybrid OCR Reader: Processes images/PDFs with Gemini Flash.
   - Cash Payment Collection: Coaches and Admins can record cash fee payments directly from the Socio profile modal.

G. OFFICIAL CLUB STORE (StoreModule.jsx)
   - Mobile: Accessible via "Tienda" tab on BottomNav.jsx.
   - Desktop: Accessible via "Tienda Oficial" on Sidebar.jsx.

H. FOOTER TEXT (App.jsx)
   - Standardized strictly to: "© 2026 Haedo Futsal App - Sistema de Gestión Integral".

6. SUPABASE DATABASE SCHEMA (users & CORE TABLES)
--------------------------------------------------------------------------------
users Table:
- id: Text format usr-[DNI] or generated text
- dni: Document text
- nombre: Full Name / Staff Name
- apellido: SURNAME in UPPERCASE (or empty for Staff)
- telefono: WhatsApp phone string
- fecha_nacimiento: Birthdate text
- hincha_de: Club preference text
- nombre_contacto: Tutor/Family contact name
- telefono_contacto: Tutor WhatsApp phone
- foto_rostro: Official face image URL/base64
- clave: 4-digit PIN (default 1234)
- rol: socio, staff, coach, contador (Adm.Club), admin
- categoria: Assigned sports category, or joined Coach categories string (e.g. "BAFI Femenino, EDEFI Baby")

Core Tables:
- notices: Institutional announcements and news.
- events: Matches, training sessions, and calendar events.
- payments: Fee payment history, OCR metadata, and audit verification states.
- push_subscriptions: Device push notification tokens.
